# Translating the demo page

As of 4.0 the demo page is translatable, entirely through WeeWX's own
mechanisms — lang files and `[Texts]`/`$gettext` — the same machinery as
WeeWX's bundled Seasons skin.  There are no invented conventions to learn:
if you have translated a WeeWX skin before, this works the same way.

![The demo page in German](https://raw.githubusercontent.com/chaunceygardiner/weewx-airlink/master/AirLinkReport-de.png)

The plots' date footers in that capture read `08/28/2026 07:20:00 AM`
rather than German dates.  Everything the lang file supplies — labels,
tabs, the year axis — is translated; the `%x %X` footers come from the C
library and follow the station's locale instead.

## How it works

Every string the page renders is a **gettext-style `[Texts]` key: the
English string is the key**.  A report falls back to English one string at
a time, so a partial translation is fine — a missing key never breaks the
page, it just renders in English.

The words come from two core-standard sources, both supplied entirely by
`lang/<lang>.conf`:

| What | Where it is translated |
|---|---|
| Page title, heading, "Unavailable", the Day/Week/Month/Year tabs | `[Texts]` |
| Observation labels — the AQI heading and every plot title | `[Labels]` `[[Generic]]` (`pm2_5_aqi`, `pm2_5`) |

The unit labels — the " AQI" suffix on a value, " RGB" — are **not**
translatable from a lang file: weewx-airlink registers them with WeeWX
itself, and that registration wins.  Both are acronyms that are left
untranslated anyway.

The lang files also localize the year plot's date axis
(`[ImageGenerator]` `[[year_images]]` `x_label_format`: day-month instead
of the US month/day).  The day, week and month axes are `%H:%M` and `%d`,
which read the same in every language.  The plots' day/date footers
(`%x %X`) are drawn in the station's own locale; on WeeWX 5.1 and later,
naming a full locale — `lang = de_DE.UTF-8` rather than `lang = de` —
localizes those too, where the station has that locale.  Since the plots
are PNG images, a language change appears as the images regenerate — the
day plots on the next report cycle, the year plot within a day.

## Translating

**German, French, Dutch and Spanish ship with the skin** — `lang/de.conf`,
`fr.conf`, `nl.conf` and `es.conf` are complete translations of the
dictionary, each kept complete by a test, so new strings cannot ship
untranslated.  The plot-period tabs are identical to the translations of
WeeWX's own Seasons skin (a test pins them).  Corrections are welcome —
[file an issue](https://github.com/chaunceygardiner/weewx-airlink/issues).
To use one:

```ini
[StdReport]
    [[AirLinkReport]]
        lang = de                # or fr, nl, or es
```

For any other language, the skin ships its reference dictionary at
`skins/airlink/lang/en.conf` — every string the page renders, and nothing
else (a test keeps it exact in both directions).  To add a language:

1. Copy `en.conf` to `<code>.conf` in the same `lang` directory (e.g.
   `it.conf`) and translate the values — the keys stay English.  Translate
   as much or as little as you like; anything you drop falls back to
   English per string.
2. Point the report at it in `weewx.conf`:

```ini
[StdReport]
    [[AirLinkReport]]
        lang = it
```

Further languages are welcome as contributions — a lang file is a
self-contained, no-code contribution.

## One place for the whole station: Defaults

Anything under `[StdReport]` `[[Defaults]]` in `weewx.conf` is merged by
WeeWX into **every** report:

```ini
[StdReport]
    [[Defaults]]
        lang = de                # every skin that ships German goes German
```

`lang = de` selects each skin's own `lang/de.conf` — Seasons, this page and
any other skin that ships German switch together.  A skin with no German
simply stays English: a missing lang file is ignored and the report falls
back, with nothing in the log at the default level (WeeWX notes it at
`debug = 1`).  A lang file that exists but will not parse is a different
matter -- that is logged as an error and stops the report.

`[[Defaults]]` (or the report's own section) is also the durable home for
local overrides: `weectl extension install` overwrites `skins/airlink/` —
including its lang files — on every upgrade, while `[[[Texts]]]`/
`[[[Labels]]]` entries in `weewx.conf` survive and are merged over them.

## The plots' fonts

The skin ships the OpenSans fonts WeeWX's own Seasons skin uses
(`skins/airlink/font/`) and draws the plots with them.  WeeWX's built-in
bitmap font cannot draw the accented characters of a translated plot
label — it renders them as boxes — so a skin whose plot titles are
translated needs a real TrueType font.

## Requirements

Nothing beyond the extension's own: weewx-airlink requires **WeeWX 4.6 or
later**, which is the release that introduced `lang` and `$gettext`.  The
demo page uses both unconditionally, so 4.6 is the floor for the whole
extension rather than a caveat on translating.

## The dictionary

The reference dictionary as shipped in 4.0 (`skins/airlink/lang/en.conf`
in the installed extension is always the authoritative copy for your
version):

```ini
[Labels]

    [[Generic]]
        pm2_5_aqi = Air Quality Index
        pm2_5     = PM2.5

[ImageGenerator]

    [[year_images]]
        x_label_format = %m/%d

[Texts]

    "weewx-airlink demo page" = "weewx-airlink demo page"
    "WeeWX-AirLink Demo Page" = "WeeWX-AirLink Demo Page"
    "Unavailable" = "Unavailable"
    "Day" = "Day"
    "Week" = "Week"
    "Month" = "Month"
    "Year" = "Year"
```
